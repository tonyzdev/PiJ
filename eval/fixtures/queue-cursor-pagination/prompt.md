Repair cursor pagination for the moderation queue. Production has many tickets with the same timestamp, timestamps differing only in microseconds, and different priorities. Reviewers see missing tickets when moving forward and wrong pages when moving backward or changing filters.

Preserve createModerationQueue(tickets) and queue.list(context, options) from src/index.js. Canonical display order is createdAt DESC, then priority DESC, then id ASC using ASCII string order. createdAt is a valid UTC ISO timestamp with exactly six fractional digits; retaining microseconds is required. IDs are unique ASCII strings and priorities are integers 0..9. Always return items in canonical order, even for backward requests. The repository can remove a ticket via queue.remove(id); cursor continuation must still work after its anchor was removed.

list({ tenantId }, { statuses?, limit?, after?, before? }) returns { items, nextCursor, previousCursor }. statuses defaults to ['open']; allowed values are open, closed, snoozed. Treat statuses as a set: reordered or duplicate entries are equivalent. The set must be nonempty. limit is an integer 1..50, default 10. Scope every query to its tenant AND normalized status set. A cursor is bound to that scope but not to limit or travel direction. after selects the nearest next limit tickets strictly after its complete ordering tuple; before selects the nearest previous limit tickets strictly before it. Boundaries are exclusive. nextCursor is based on the last returned ticket only when another matching ticket exists after it, and previousCursor on the first returned ticket only when one exists before it; otherwise return null. Empty pages return both cursors null. Cursors must remain usable in either direction and across page-size changes.

Reject simultaneous after/before, invalid query values, malformed tokens, unsupported cursor versions, missing or incorrectly typed ordering fields, and scope mismatches. Expose code INVALID_QUERY for query validation and INVALID_CURSOR for cursor validation via the existing errors. Do not silently reset to page one on invalid tokens. Keep the existing base64url JSON envelope { version: 1, scope, key }, with key { createdAt, priority, id }; the scope representation may change to bind the whole query. Tokens are opaque continuation data, not authentication, and no signing service is needed. Preserve the activity feed and summary behavior. Do not use offsets for queue pagination, add dependencies, or hardcode fixture rows. Add regression tests and run npm test; starter smoke tests do not cover all ordering and boundary cases.
